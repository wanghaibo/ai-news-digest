1. [zed-industries/zed](https://github.com/zed-industries/zed) +1,114⭐ [Rust]

Zed 把高性能多人代码编辑器与多种 agent 工作方式放在同一界面。除原生 Zed Agent 外，它可通过 ACP 接入外部 agent，或以终端线程运行 CLI；线程侧栏支持跨项目和 worktree 并行工作，模型也可选托管服务、自有 API 或本地模型。对已有编码 agent 的团队，价值在于把上下文、改动审阅和并行任务收进编辑器；外部 agent 仍沿用自己的进程和配置，需要分别核对模型、工具与数据边界。

补充来源：[Zed 官方 AI 功能文档](https://github.com/zed-industries/zed/blob/main/docs/src/ai/overview.md)

2. [ranxianglei/billion-context](https://github.com/ranxianglei/billion-context) +191⭐ [TypeScript]

billion-context 在编码 agent 与模型 API 之间压缩会话历史，帮助长任务在有限上下文窗口内持续运行。模型可调用 compress 将一段消息折叠成摘要，再用 decompress 恢复细节，或用 search_context 搜索历史；增量处理还试图保留前缀缓存。它管理的是累计会话而非扩大模型的原生窗口，适合研究长周期 coding-agent 工作流；README 仍标注早期阶段，实际模型集成与稳定性需要自行验证。

3. [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser) +190⭐ [Rust]

agent-browser 给 AI agent 提供可逐步执行的浏览器命令行。snapshot 把页面转成带元素引用的紧凑无障碍树，agent 根据引用点击或填写，再读取页面验证结果；后台进程通过 Chrome DevTools Protocol 保持会话，也可经 MCP 接入。它适合把网页操作纳入可检查的工具循环，但元素引用只对应当时页面，导航或 DOM 改动后必须重新取快照，不能反复使用旧引用。

4. [Usagi-org/ai-goofish-monitor](https://github.com/Usagi-org/ai-goofish-monitor) +144⭐ [Python]

ai-goofish-monitor 把闲鱼商品搜索、图文判断与提醒串成可配置的监控任务。Playwright 采集商品详情和图片，多模态模型按自然语言需求筛选，结果与价格历史写入 SQLite，并可按 Cron 调度、通过企业微信或 Webhook 通知。它适合持续筛选特定二手商品，但依赖账号登录态与支持图片输入的模型；应保护登录态、修改默认管理口令，并遵守平台规则控制访问频率。

5. [dsx-ai-factory/nvke](https://github.com/dsx-ai-factory/nvke) +123⭐ [Go]

NVKE 是供平台团队在自有 NVIDIA GPU 基础设施上运营 Kubernetes 集群的管理平面。它通过 NICo 提供机器，为每个工作负载集群建立独立控制平面、etcd 和节点池，并使用 TPM 与 SPIFFE/SPIRE 验证节点身份。适合评估自建 AI 基础设施的多集群服务，但目前仍是 preview，官方不建议用于生产；默认 API 未启用认证且使用 HTTP，评估前必须配置受保护访问。
