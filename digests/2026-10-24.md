#### [Rapidly scaling online storage to serve over 1 billion ChatGPT users (Part II)](https://openai.com/index/scaling-storage-one-billion-users-part-two/)

Habitat 回归多租户：把全球读取中位延迟从约 120ms 降至 10ms

发布时间：2026-10-23

Jon Lee、Hrachya Hakobyan 和 Chaomin Yu（三人均为 OpenAI 技术团队成员）披露，Habitat 存储平台从共享容器转向单租户后，因容量规划分散又回归默认多租户。解法是热点 key 限流、交互请求优先的 QoS，以及可移动数据的路由层；缓存通过 Cosmos DB 的变更流在数秒内传播失效，再结合关键数据就近复制和 Rust 重写，全球读取 p50 从约 120ms 降至 10ms。对大规模 AI 产品，隔离、容量和延迟需要共同设计；12 倍是组合改造后的中位数改善，不是 Rust 单项收益，未命中缓存的长尾请求仍可能跨区读取。

作者背景：Jon Lee、Hrachya Hakobyan 和 Chaomin Yu，均为 OpenAI 技术团队成员（Members of Technical Staff）；身份由本文署名直接确认。

1. [NVIDIA/OpenShell](https://github.com/NVIDIA/OpenShell) +1119⭐ [Rust]

OpenShell 把 agent 的安全边界放在运行时，而不是只靠提示词约束行为。它用内核控制限制文件、系统调用与网络访问，让隔离区外的 supervisor 审核请求，并只向批准的服务注入真实凭证，agent 本身不直接接触密钥；策略变更还会经过形式化检查，新增高风险权限留待人工审阅。这适合需要读写工作区、安装依赖和调用 API，却不能获得整台机器权限的自主编码助手。部署边界也很具体：默认镜像不自带 agent，Kubernetes 环境须由网络插件真正执行 NetworkPolicy；形式化检查针对策略变化，不等于证明模型输出或整个应用绝对安全。 本日报首次收录，不代表项目今日发布或首次登上全站 Trending。

3. [virgiliojr94/book-to-skill](https://github.com/virgiliojr94/book-to-skill) +143⭐ [Python]

book-to-skill 把技术书、文档文件夹或多份资料编译成按需读取的 agent 技能，而非一次性长摘要。确定性的 Python 提取器先取得正文与元数据，再由 agent 生成核心概念、章节索引、术语表和决策速查表；提问时只加载有关章节，适合反复查阅工程手册或团队规范。典型结构约含 4000 token 核心文件和每章约 1000 token 分文件，可接入 Claude Code、Codex 等采用 Agent Skills 格式的宿主。扫描 PDF 须先做 OCR，复杂表格需选对提取器；本地提取不等于云端模型不会收到正文，转换内容仍受原资料权利约束。 本日报首次收录，不代表项目今日发布或首次登上全站 Trending。
