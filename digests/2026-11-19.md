### Vercel

#### [Introducing Vercel Board](https://vercel.com/blog/introducing-vercel-board)

Vercel Board：把任务认领、上下文和权限放进共享消息层

Board 是实验性的 agent 消息与协调基础设施，通过 CLI 或 JavaScript SDK 使用，不绑定模型、运行框架或托管平台。频道与线程保存任务讨论、认领状态和结果；依赖满足后任务才能开始，也能由事件或定时回访唤醒 agent。结构化消息按 schema 校验，grants 限制频道访问，事件保留操作身份。它解决的是跨工具协作状态，不保证任务质量；Slack/GitHub 同步及沙箱权限仍需正确配置。

与 Vercel Sandbox 配合时，SDK 可生成限定 Board 频道与操作的访问策略，避免把凭证放进沙箱。官方示例同时允许 npm 网络访问，因此不能泛化成无外网的隔离环境。

署名为 Julian Benegas、Nicolás Montone、Malte Ubl、Tom Knickman、Martin Sione、Bani Singh，均为本篇 Vercel 官方文章作者；各人当前具体职衔未逐一核实。

### Google / The Keyword

#### [Introducing Stitch Loop: A new way to build and evolve products](https://blog.google/innovation-and-ai/models-and-research/google-labs/stitch-loop/)

Stitch Loop：持续看反馈，但合并代码仍需人审核

Stitch Loop 把产品改进组织成建议、方案、构建、复盘四步：接入代码与行为反馈，提出有依据的机会，在隔离云沙箱中生成可审查的 PR，再持续观察上线后的指标和回归。关键边界是未经人工审查不合并 PR。其价值在于把产品反馈连接到持续执行，而非让 agent 自行决定一切。当前开放全球候补名单，符合条件的 Google AI Ultra 用户优先，不是所有人已可直接使用。

可接入 180 多种集成，也支持自定义 MCP 和本地 CLI 上传上下文；安全、性能、可访问性是默认关注方向，团队可另设业务目标。

Justin Toupin，Google Labs 产品管理总监，为官方署名作者。

发布日期：2026-11-18

#### [Introducing Gemini 4 Neon](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)

Gemini 4 Neon：比较任务成本，而不只比较 token 单价

Google 发布 Gemini 4 Neon，支持 100 万 token 上下文和四档思考强度；high 为默认档，xhigh 面向更难任务。标准 API 每百万 token 输入、缓存输入、输出分别为 3、0.15、15 美元。Google 报告 high 档在 Artificial Analysis 指标上的每任务成本较 Carbon 低 32%，这是特定评测口径，不是每种工作负载的固定折扣。部署时应以自己的正确率、延迟和总 token 消耗验证路由策略。

常规模型进入 API、AI Studio 及相应产品入口；面向可信防御者的 Neon for cyber 经 Fairwind 提供，计划在随后几天推出，不能与普通模型的可用范围混同。

Koray Kavukcuoglu，Google DeepMind 高级副总裁、Google 首席 AI 架构师，为官方署名作者。

### OpenAI

#### [Advancing chip design with OpenAI models](https://openai.com/index/advancing-chip-design-with-our-models/)

AI 优化芯片：验证 RTL 等价性，也要审视评测删掉了什么

OpenAI 报告模型参与 AMD 及 Jalapeño 芯片优化：改写 SystemVerilog RTL 后，用验证工具检查行为，再比较功耗、性能与面积；AMD 案例自报 PPA 最多改善 14%。另一个开源 RISC-V 评测允许从规格重新设计，因此可能不保留原实现的性能计数器或附加指令。这个边界很重要：评测得分不能直接等同于完整生产芯片收益。对工程团队，更值得复用的是明确约束、自动验证与测量闭环。

RISC-V 评测对仿真失败或面积超过基线 16 倍的结果计零分，性能结合隐藏负载 IPC 与综合估算频率；它仍不等同于完整物理实现后的时序验收。
