### The InfoQ Podcast

#### [Simulation Can Tell You What Your Agents are Actually Doing: A Conversation with Zhou Yu](https://www.infoq.com/podcasts/simulation-agents-actually-doing/)

测多轮 Agent，别只刷标准答案

俞舟（Zhou Yu，哥伦比亚大学计算机科学副教授、DAP Lab 联合负责人及 Arklex.ai 联合创始人）建议测多轮 Agent 时固定测试场景和目标，而不是固定每句输入和答案。模拟用户带着目标、偏好与背景同 Agent 互动；Agent 的回复变了，模拟用户可追问或改口。规则验证器再独立检查目标是否完成，另记成本、效率和合规。测试可用于原型验证、发布回归和上线巡检，失败时还能查对话与工具调用。不等于模拟用户能代替真实用户：业务专家还需补异常场景，用生产反馈反查覆盖盲区。

证据：InfoQ 官方单集逐字稿。俞舟谈模拟质量时问：“are they actually having coverage?”（约 28:24 章节）。

俞舟（Zhou Yu）是哥伦比亚大学计算机科学副教授、DAP Lab 联合负责人及 Arklex.ai 联合创始人。她在卡内基梅隆大学获语言技术博士学位，研究对话系统、自然语言处理与人机交互；公司案例是受访者经验。

### Hugging Face 官方博客

#### [How to build and maintain an agentic evaluation](https://huggingface.co/blog/agentic-evals)

先验评分器，再给 Agent 打分

Hugging Face 用 Harbor 搭了 8 个合成拉曼光谱任务。参考解应过、空跑应败；再加一个只交正确比值、不真正拟合的反例，发现旧评分能被蒙混，才补验峰形拟合。在同一组 24 次尝试中，gpt-oss-120b 过了 11 次：8 个任务里至少成功一次的有 7 个，连续三次都成功的只有 1 个。允许人工复核重试和希望无人值守稳定运行，显然不能看同一项指标。

每任务试 3 次。会话轨迹暴露了多次过早宣布完成的问题，不能一律归咎于物理拟合能力。这组任务是开发集，不代表更复杂的真实测量，也不足以给全过的模型排位。源码加入时间可核对，不作为精确网页首发时间。

Avijit Ghosh 是 Hugging Face 技术 AI 政策研究负责人；Ben Burtenshaw 是文章和公开评测工件的维护者；Irene Solaiman 是 Hugging Face 首席政策官。

### Claude 官方资源库

#### [Introducing Claude Ship](https://claude.com/resources/articles/introducing-claude-ship)

Claude Ship 开测：修 PR 和准 PR 分给不同角色

Claude Ship 把 GitHub PR 拆成三个环节：Code Review 提出问题，PR Steward 处理评审反馈、失败的 CI 与冲突，Claude Approvals 按仓库里的团队规则决定何时能批准、何时必须转给人。Steward 修完会留下变更与撤销说明，本身不批准也不合并。团队可先选一个仓库让审批只观察，再决定是否纳入分支保护。

Code Review 已正式可用；PR Steward 和 Claude Approvals 仍是 beta，整套仓库级功能面向 Team 和 Enterprise。开发者也能用 Claude Code 的 /ship 处理自己的 PR；是否实际可合并，由人员权限、仓库规则和需要通过的检查共同决定。

发布日期：2026-11-23

GLM-5.4：共享权重的 28 层跑两遍

智谱在 GLM-5 底座上让一段共享权重的 28 层连续运行两遍，第二遍接着修正第一遍的中间表示，而不是为每一层增加一套独立参数。GLM-5.4 还加入视觉输入，官方用网页、游戏和 CAD 任务做演示。现有 GLM Coding Plan 全档位可切换；换到更高思考档仍可能消耗更多 token。

### Google DeepMind 官方博客

#### [Finding faster quantum algorithms with agents and formal verification](https://deepmind.google/blog/finding-faster-quantum-algorithms-with-agents-and-formal-verification/)

Gemini 4 找电路，Lean 检查是否等价、用多少资源

Google DeepMind 让 Gemini 4 的 Agent 团队在已有形式化规格下寻找更便宜的量子电路，再用 Lean 核查功能正确性与成本。在一项惯性约束聚变模拟里，按论文的资源估算口径，混合优化方案的成本指标改善约 11.8 倍；这是对未来容错硬件的估算，不是实际量子硬件上的加速实测。
