### The Every Podcast

#### 工程经理的杠杆是看见瓶颈，而不是多消耗 token

原题：[Why Every Traded Personal Agents for One Company Agent](https://every.to/podcast/transcript-why-every-traded-personal-agents-for-one-company-agent)

核心要点：把信息收集与初步分派交给 agent，经理的主要工作仍是找到瓶颈、协调人与决策。

**Willie Williams**（Every 平台负责人）曾创办 Mori 并任 CEO，也曾负责 Lyft 的 AI 运营；他主导 Every Agent 工程落地，判断来自实际建设和维护团队系统的经验。主持人 **Dan Shipper**（Every 联合创始人兼 CEO）把团队从个人 bot 转向共享 agent 的过程，作为追问这些经验的起点。

Willie Williams 用 Tend 汇总 Slack、邮件和客户反馈，从产品开发之外看见发布与营销进度；指标巡检则让 agent 每五分钟查找异常并路由提醒。AI 扩大了他的观察范围，但需要采取行动时，最有用的往往是和相关同事谈清问题，因此他回到工程管理后，token 使用量反而下降。Dan Shipper 进一步推测，共享 agent 可能按团队需求逐渐分化。对管理者的启发是先明确哪些信息值得进入视野，再自动化收集；这些仍是 Every 的内部经验与预测，不能直接当作普遍组织定律。

### Anthropic

#### Haiku 5.5 降低高频小任务成本，Sonnet 缓存读取同步降价

原题：[Claude Haiku 5.5](https://www.anthropic.com/claude-haiku-5-5)  
发布日期：2026-10-07。作者：Anthropic。

Haiku 5.5 把可调 effort 带入小模型，定位摘要、分类、上下文压缩及范围明确的子 agent 工作。提示长度不超过 100K tokens 时，每百万输入／输出 tokens 为 0.10／0.50 美元；超过后分别为 0.50／2.50 美元。Sonnet 5.5 的缓存读取也减半至每百万 tokens 0.10 美元。对高频工作流，更低的单次成本扩大了可尝试的自动化范围；但复杂 agent 编程仍需评估更大模型。厂商所称约 75% 的平均任务成本下降还考虑了 tokenizer 和 token 使用量变化，不能当作每个任务的固定节省比例。

### OpenAI

#### GPT-6 把回答变成可交互界面，并能边思考边交付

原题：[GPT‑6 and Intelligent UI for everyone](https://openai.com/index/gpt-6-for-everyone/)  
发布日期：2026-10-07。作者：OpenAI。

Intelligent UI 的实现是原生、可流式输出的组件库与增量编译器：模型决定何时使用图表、按钮或交互工具，界面无需等整段生成结束才出现。训练同时评估布局、清晰度和实用性，回答也能先给已有结论，再补充后续思考。付费档使用 Sol，Free／Go 使用 Luna；10 月 7 日先向付费档推出，8 日开始扩展免费档。这意味着 Chat 的输出可以直接成为临时工具，但不代表所有账号已完成上线，也不改变 Work 或 Codex 的模型。[更新说明](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)另明确：Pro 推理选项仍用 Astra，不支持 Intelligent UI。

### Liquid AI Blog

#### 开放 d1 小模型，把多模态判断压到一次前向计算

原题：[Open d1: Edge decision models for text, vision, and audio](https://www.liquid.ai/blog/d1-open)  
发布日期：2026-10-07。作者：Liquid AI。

d1-3B 和实验版 d1-omni-600M 输出结构化判断，不需要逐 token 生成长回答。前者接收文字与图像，后者支持文字配图像或音频，发布即支持 llama.cpp。官方逐个请求测试里，d1-3B 在 RTX 4090 上回答一个问题用时 8 毫秒，处理 3.4K-token 输入则需 102 毫秒；在 Jetson Orin Nano 上，同样两类输入为 50 与 1,640 毫秒。这个差别提醒边缘应用开发者，实时性取决于实际输入。600M 版仍处于研究阶段，官方未报告私有视觉集成绩，专门的音频决策评测也尚不成熟。

### Every · Context Window

#### 降本之前，先找出系统正在重复处理什么

原题：[Building a More Efficient Agent](https://every.to/context-window/building-a-more-efficient-agent)  
发布日期：2026-10-07。

**Laura Entis**（Every 专职作者）记录了 **Paridhi Agarwal**（Every 工程师）的优化复盘：先让便宜模型分派任务，反因两次处理而增加成本、拖慢回答。更大的机会藏在缓存里，用户 Slack ID 被带入系统提示，破坏了跨用户复用。统一对模型可见的文件夹名、保留实际记忆隔离后，缓存才恢复。团队称升级模型与多项修复，让 11 类常见任务成本合计下降逾 80%；缓存修复在最佳测试里省下 74%，不能外推到所有任务。可复用的方法是先读代码和当前文档，再逐项改动，用同一组任务同时测量成本、速度与质量，而非先增加复杂路由。

### Windows Developer Blog

#### MXC 正式可用：agent 权限成为可测试的运行时边界

原题：[Microsoft Execution Containers: Policy-driven containment for AI agents](https://blogs.windows.com/windowsdeveloper/2026/10/07/microsoft-execution-containers-policy-driven-containment-for-ai-agents/)  
发布日期：2026-10-07。

**Logan Iyer**（Microsoft Windows Platform + Developer 企业副总裁）宣布 MXC 正式可用。开发者用统一 JSON 配置声明可访问的文件、网络和界面，再由容器在运行时执行限制；agent 无法自行修改策略来扩权。进程容器支持 Windows、macOS 和 Linux，独立桌面的会话容器仅支持 Windows。策略调试要分清两种模式：Learning 会阻止并记录越界访问，Permissive 只记录并继续放行。对本地 agent 团队，这让最小权限可以通过任务测试来迭代，但不同后端隔离强度不同，MicroVM 仍属实验，Entra 身份区分和部分集中管理能力也尚待推出。

1. **[morluto/rea](https://github.com/morluto/rea) +4,655⭐ [TypeScript]**

**把 app 与二进制分析接入 agent 的证据链。** REA 通过本地 MCP 与 CLI，把原生二进制、JavaScript/Electron、.NET 和网站的检查工具交给 coding agent。它返回代码、引用关系、运行观察及结论的证据与未知点，agent 可以继续追问、解释行为并验证重建结果；适合授权范围内的兼容性研究和旧系统理解。原生分析依赖 Hopper、Ghidra 或 IDA 等后端，静态 JavaScript 分析则不需要这些引擎；动态采集会以当前用户权限运行或操作目标，不能把“本地分析”当作天然隔离。

README 给出的一个具体工作流是追踪 Electron 应用的剪贴板 API，沿 preload 与 IPC 走到主进程；重点是把功能行为连回可检查的实现路径，而不是只让模型猜测 UI。

2. **[cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill) +576⭐ [JavaScript]**

**把漏洞发现与证据复核分给独立 agent。** 这套 coding-agent skill 把单仓库安全审计拆为侦察、按覆盖表分派搜查、候选验证、结构化输出、独立记录复核和报告六个阶段。每条候选交给新的 verifier 尝试证伪，并区分 confirmed、needs_validation 与 rejected，覆盖表和 JSON 校验器让后续审计能补缺口，而不是重复一轮泛泛扫描。适合研究多 agent 审计的证据组织方式；README 要求对目标代码的执行使用操作系统级沙箱、禁外网及资源限制，条件不足时保留为待验证，不能直接确认漏洞。
